# ServerMaster 多服务器批量管理工具 — 设计文档

> 版本：v0.1（M1 里程碑） 日期：2026-10-24

---

## 1. 需求理解

| 编号 | 需求 | 说明 |
|------|------|------|
| R1 | 多画面同屏观看 | 在一个程序窗口内，同时观看多台 Windows Server 上运行的程序界面（实时桌面） |
| R2 | 单服务器操作 | 点击任意画面即可像本机一样操作该服务器的桌面/程序 |
| R3 | 多服务器同步操作（广播） | 把键盘/鼠标输入同时发给一台或多台服务器，实现"批量下发操作" |
| R4 | 文件传输 | 向单台或多台服务器上传/下载文件（批量分发部署包等） |
| R5 | 服务器配置管理 | 分组管理服务器清单，保存凭据，快速连接/断开 |

## 2. 可行性结论

**结论：完全可行，且属于已被业界充分验证的成熟技术路线。**

同类商业/开源产品先例：

| 产品 | 证明点 |
|------|--------|
| mRemoteNG（开源） | WinForms 内嵌微软官方 RDP ActiveX 控件（mstscax），单窗口管理大量 RDP 会话 |
| Remote Desktop Manager | 标签/平铺多会话 + 文件传输 + 凭据库 |
| Royal TS | 多画面平铺 + 输入广播到多连接 |

三项核心需求的可行性逐条论证：

1. **多画面同屏（R1）**：微软官方 RDP 客户端控件 `mstscax.dll`（Windows 自带）是标准 ActiveX 控件，可在 WinForms 中以 `AxHost` 方式创建**多个实例**，每个实例独立连接一台服务器的独立 RDP 会话，各自渲染各自交互。配合 `SmartSizing=true`，远端桌面可自动缩放适配任意大小的分格画面。带宽通过色彩深度（8/16 位色）与关闭位图缓存策略控制，10 路同屏在普通办公网络可行。
2. **输入广播（R3）**：
   - 键盘：控件官方接口 `IMsRdpClientNonScriptable::SendKeys(numKeys, pbArrayKeyUp[], plKeyData[])` 允许程序以**扫描码**向远端会话注入按键——本工具在宿主窗口用 `IMessageFilter` 捕获主控会话的按键消息，镜像调用其他会话的 `SendKeys`。
   - 鼠标：`PostMessage` 向目标会话控件句柄投递 `WM_LBUTTONDOWN/UP`、`WM_MOUSEMOVE`、`WM_MOUSEWHEEL` 等消息，坐标按各分格尺寸线性换算（因 `SmartSizing` 缩放是线性的）。
   - 该方案与"焦点跟随"兼容：主控画面正常操作，其余被选中的画面同步执行相同点击/输入。
3. **文件传输（R4）**：三条互补通道（详见 §6）——RDP 剪贴板文件重定向（零配置）、SMB 管理共享 `\\主机\c$`（管理员凭据即可、可编程批量分发）、RDP 驱动器重定向（远程会话内直接访问本地盘）。

**主要约束（诚实声明）**：

- 每台 Windows Server 默认允许 **2 个并发管理用 RDP 会话**（更多需 RDS 授权）。本工具对"N 台服务器各 1 路"没有限制。
- 广播鼠标为"坐标镜像"近似实现：个别捕获拖拽的窗口内行为可能不完全一致；键盘广播对扩展键（Win/AltGr）使用扫描码扩展前缀，标注为实验特性。
- 密码以 Windows DPAPI（当前用户作用域）加密存储，**导出配置到其他机器后需重新录入密码**（安全设计使然）。
- 必须运行在 Windows 管理机上（RDP ActiveX 为 Windows 组件）。

## 3. 技术选型

| 备选方案 | 优点 | 缺点 | 结论 |
|----------|------|------|------|
| A. WinForms + mstscax ActiveX（**选定**） | 微软官方控件、兼容性最好、.NET Framework 4.8 零部署、mRemoteNG 验证过 | 仅 Windows | ✅ |
| B. WPF + WindowsFormsHost 套 ActiveX | UI 更现代 | 双 UI 栈复杂度高，无本质收益 | ❌ |
| C. FreeRDP 自绘渲染 | 跨平台 | 需 C 库编译/协议栈自实现，工作量大数倍 | ❌ |
| D. 服务器端 Agent 截屏流 | 可控性强 | 需在所有服务器部署 Agent，侵入性强、安全风险 | ❌ |
| E. VNC | 简单 | 需额外装 VNC Server、无加密、体验差 | ❌ |

- **目标框架**：.NET Framework 4.8（Win10 1903+/Server 2019+ 操作系统自带运行时，**exe 拷过去就能跑**）
- **UI**：WinForms（ActiveX 宿主原生支持）
- **RDP 互操作**：`AxImp.exe` 从系统 `mstscax.dll` 生成的 `AxMSTSCLib.dll` + `MSTSCLib.dll`（已生成，存于 `lib/`）
- **配置存储**：JSON（`JavaScriptSerializer`，零外部依赖），路径 `%APPDATA%\ServerMaster\`
- **密码加密**：Windows DPAPI（`CryptProtectData`，CurrentUser 作用域 + 固定熵）
- **代码风格**：C# 5 兼容（本仓库附带的 `build.cmd` 可用系统自带编译器离线构建）

### 模块职责

| 模块 | 职责 |
|------|------|
| `Rdp/RdpSession` | 封装单个 RDP ActiveX：连接参数、连接/断开、状态机（断开→连接中→已连接→重连中→失败）、意外掉线自动重连、扫描码注入 |

| `Services/FileTransfer/SmbChannel` | `WNetAddConnection2` 建立凭据会话后经 `\\主机\c$` 管理共享上传/下载（支持批量多服务器） |

## 5. 关键技术设计

### 5.1 多画面（RDP 会话分格）

- 每个分格 = 一个 `SessionTile`，内含一个独立的 `AxMsRdpClient9NotSafeForScripting` 实例。
- 连接参数要点：
  - `SmartSizing=true`：远端画面缩放至分格大小（核心）；
  - `ColorDepth` 可选 8/16/24 位（多路同屏建议 16 位，观看型分格可降到 8 位）；
  - `DesktopWidth/Height` 取分格初始尺寸，保证 1:1 清晰度后再缩放；
  - `ConnectToAdministerServer`（控制台会话）可选；
  - `EnableCredSspSupport=true` 支持 NLA；`ClearTextPassword` 注入凭据实现免交互登录；
  - `GrabFocusOnConnect=false`：新连接不抢焦点，避免批量连接时焦点乱跳；
  - 关闭打印机/智能卡/端口重定向，`RedirectClipboard=true` 保留文件传输能力，`RedirectDrives` 按需。
- 布局：`SessionGridPanel` 纯自绘布局，列数 = 自动（⌈√n⌉）或固定 1~4 列；双击标题栏放大为"满幅模式"（其余分格隐藏），再次双击还原。

### 5.2 输入广播（镜像机制）

```
用户键鼠 ──▶ Windows 消息队列 ──▶ 主控分格的 mstscax (正常处理)
                    │
                    ▼ PreFilterMessage (IMessageFilter, 不拦截只旁听)
        InputBroadcastService 判定: 消息目标 == 主控会话句柄 && 广播开启
                    │
          ┌─────────┴──────────┐
          ▼ 键盘                ▼ 鼠标
   提取 lParam 扫描码       提取 lParam 客户区坐标
   (+扩展键标志)            按目标分格尺寸线性换算
          │                       │
          ▼                       ▼
   target.SendKeys(...)     PostMessage(target.Handle, WM_LBUTTONDOWN, ...)
   (RDP 官方注入接口)        (鼠标窗口消息注入)
```

- **主控会话**：最近一次被点击的分格；**广播目标**：分格标题栏"广播"勾选框被勾上的会话（提供全选/清空）。
- 键盘：`WM_KEYDOWN/UP`、`WM_SYSKEYDOWN/UP`；`lParam` 第 16-23 位为扫描码、第 24 位为扩展标志；对扫描码为 0 的注入键（输入法合成），用 `VkKeyScan` 反查虚拟键再映射扫描码兜底。组合键（Shift/Ctrl/Alt 按住）天然正确：修饰键本身也是消息，同样被镜像。
- 鼠标：左/右/中键、双击（两次 down/up 序列自然还原）、滚轮、X 键；拖拽 = down→move…→up 序列自然镜像；`WM_MOUSEMOVE` 仅在有按键按下或按 30ms 节流镜像，避免消息洪泛。
- 设计上"广播"是**叠加**而非"抢占"：主控分格永远正常响应用户（R2），其余被勾选分格同步执行（R3）。

### 5.3 文件传输（三通道互补）

| 通道 | 原理 | 适用场景 | 服务器要求 |
|------|------|----------|-----------|
| ① SMB 管理共享（主通道，可编程批量） | `WNetAddConnection2` 以管理员凭据连接 `\\主机\IPC$` 后，直接对 `\\主机\c$\路径` 做流式复制 | 批量分发部署包到 N 台；下载日志 | 开放 445，管理员账号（默认共享 C$ 可用） |
| ② RDP 剪贴板 | 本地 `Clipboard.SetFileDropList(CF_HDROP)` → 远端会话 Ctrl+V（RDP 剪贴板重定向自动同步文件） | 快速把文件丢给当前正在操作的会话；配合广播 Ctrl+V 可一次粘贴到多台 | 无（RDP 默认能力） |
| ③ 驱动器重定向 | `RedirectDrives=true`，远程"我的电脑"出现 `\\tsclient\C` | 会话内临时浏览/拖拽本地文件 | 无 |

`FileTransferForm` 支持勾选多台已连接/清单内服务器，指定本地目录与远端目录，后台线程逐台执行上传（目录自动创建、同名覆盖），实时进度与逐文件日志；下载为反向复制。典型错误码翻译：5=凭据/权限、53=网络不通或 445 未开放、1219=凭据冲突（提示先清除已存在的 Windows 凭据会话）。

### 5.4 FinalShell 批量导入

把用户在 FinalShell 里积累的服务器清单（含分组、凭据）一键迁移进本工具。两种来源：

| 来源 | 说明 |
|------|------|
| 导出文件 | FinalShell 连接管理器右键"导出"生成的 `.json`（数组/单对象/带分组嵌套均可） |
| conn 目录 | 直接选择 FinalShell 数据目录 `%APPDATA%\finalshell\conn`（或安装目录下 `finalshell\conn`），每个连接一个 `.json`，**子目录名自动还原为分组** |

- **解析容错**：递归钻取数组/包装对象/嵌套分组节点，无 `host` 的条目跳过；未知字段忽略；单文件损坏不影响整体。字段名兼容两代：4.x 用 `user_name`/`conection_type`（101=RDP），旧版用 `username`/`protocol`。
- **密码迁移**：FinalShell 存储密码为 `Base64( 8字节头 + DES-ECB-PKCS5(密码) )`，密钥派生分两代算法，解码时按候选依次尝试、首个成功者胜出：
  - **4.x（当前主流）**：`ks = 3680984568597093857 / Random(head[5]).nextInt(127)` → `Random(ks)` 丢弃 `head[0]` 次 `nextLong` 取下一个 → 与 `Random(该值)` 的两个 `nextLong` 及 `head[4]/[7]/[3]/[1]/[2]` 交错组成 8 个 long（Java 大端序 64 字节）→ **MD5 前 8 字节**为 DES 密钥（JDK 秘钥工厂路径可能做奇偶校验位修正，两种候选都尝试）；
  - **旧版（≤3.x）**：DES 密钥 = `Random(头8字节大端 long).nextBytes(8)`。
  本工具在导入时于**本机内存中解密并立即以 DPAPI 重新加密落盘**（等价于用户手工重录密码，不改变安全边界）。解密失败的条目标记"需手动录入"，不阻断导入。
- **分组还原**：conn 目录模式下逐级读取 `folder.json`（4.x 子目录名是内部 ID）；`阿里云` 等空分组不产生条目。分组框留空 = 按 FinalShell 原分组；填写 = 全部归入指定分组。
- **去重**：按"主机+端口"（归一化 `host:port` 后）双重去重——与现有清单比对（"已存在"置灰不勾选）、批内互相比对（FinalShell 移动连接后可能残留旧文件，"批内重复"置灰不勾选）。
- **协议透明**：清单显示协议列。RDP 条目可直接连接；SSH 条目保留原始端口（RDP 接入需自行修改端口），备注标注来源协议。

### 5.5 会话状态机与自动重连

```
 Disconnected ──Connect()──▶ Connecting ──OnConnected──▶ Connected
      ▲                        │                            │
      │手动断开/重试耗尽          OnLogonError/                 意外掉线(非用户断开)
      │                        OnFatalError                  且 AutoReconnect=true
      ├────────────────────────┴──────────▶ Failed          │
      ◀──────── 重试间隔5s×最多5次 ◀────── Reconnecting ◀────┘
```

`OnDisconnected` 的 `discReason=260` 为客户端主动断开；其余代码视为意外掉线进入重连（每会话独立 `Timer`）。状态灯：灰=断开、黄=连接中/重连中、绿=已连接、红=失败（悬停显示原因码）。

## 7. 安全设计

- 密码仅以 DPAPI（CurrentUser + 应用熵）密文落盘，内存中解密后立即交给 RDP 控件，不回显。
- RDP 启用 NLA（CredSSP）；SMB 通道凭据仅存在于本次 `WNetAddConnection2` 会话，传输完即 `WNetCancelConnection2` 清除。
- 配置导出提示：密码密文仅在本机本账户可解。
- 不内置任何后门/旁路；工具仅以使用者提供的凭据执行操作，写入审计日志。

## 9. 限制与风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 单服务器并发 RDP 会话数限制（默认 2） | 同一服务器开多路受限 | 设计上"一服务器一路"；文档说明 RDS 授权 |
| N 路同屏带宽 | 网络拥塞 | 色彩深度/分辨率下调；分格"仅观看"档 8 位色 |
| 广播鼠标保真度 | 个别程序内拖拽行为差异 | 文档标注；主通道操作不受影响 |
| mstscax 版本差异（Win7/8 管理机） | 接口缺失 | 目标管理机 Win10+；连接参数集中在 RdpSession 便于适配 |
| SMB 管理共享被禁用 | 通道①不可用 | 错误码明确提示；回退通道②③ |
| 密码跨机不可解（DPAPI） | 换机需重录 | 设计取舍（安全优先），导出对话框提示 |

## 10. 里程碑

- **M1（本次交付）**：架构 + 多画面同屏 + 单画面操作 + 键盘/鼠标广播 + 服务器分组管理 + JSON/DPAPI 配置 + SMB 批量文件传输 + 剪贴板推送 + 自动重连 + 日志。
- **M2**：传输队列/断点续传与校验、会话截图/录像、键盘宏（批量执行命令序列）、凭证库（主密码加密全部凭据）、连接前端口探测。
- **M3**：性能监控面板（CPU/内存/磁盘 via WMI）、批量计划任务、权限分级、多标签工作区。
