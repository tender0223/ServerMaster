# 04 · 核心实现：多画面与输入广播

> 《从零写一个多服务器 RDP 批量管理工具》第 4 篇。[系列目录](00-系列总览.md)

这一篇是整个项目技术含量最高的部分：RDP 会话封装、键盘扫描码注入、鼠标坐标镜像。

## RdpSession：把 ActiveX 的脏活全部包起来

每个服务器一个 `RdpSession`，持有独立的 `AxMsRdpClient9NotSafeForScripting` 实例。连接参数的每一项都有理由：

```csharp
a2.SmartSizing = true;           // 核心：远端画面等比缩放适配分格
a2.GrabFocusOnConnect = false;   // 批量连接时不抢焦点，否则焦点乱跳
a7.EnableCredSspSupport = true;  // NLA 网络级认证
a2.ClearTextPassword = pwd;      // 凭据注入，免交互登录
a7.RedirectClipboard = true;     // 保留剪贴板通道
a2.RedirectPrinters = false;     // 多路同屏时砍掉无用重定向，省资源
```

一个重要设计：**可选参数逐项容错**。老系统可能不支持 `RedirectClipboard` 这类属性，一项失败不该拖垮整个连接：

```csharp
private void TrySet(string name, Action setter)
{
    try { setter(); }
    catch (Exception ex) { AppLogger.Warn("参数 " + name + " 设置失败(已跳过): " + ex.Message); }
}
```

自动重连的状态机在 02 篇画过，实现要点是区分"主动断开"（`discReason == 260`）和意外掉线，只有后者进 5 秒 × 5 次的重连循环。

## 键盘广播：扫描码注入

RDP 官方接口 `IMsRdpClientNonScriptable::SendKeys` 接收的是 **PS/2 Set-1 扫描码**，不是虚拟键。所以先建一张 `Keys → 扫描码` 映射表（KeyMapper，含扩展键标志），然后从 Windows 消息里提取扫描码镜像注入：

```csharp
// WM_KEYDOWN 的 lParam：第 16-23 位是扫描码，第 24 位是扩展键标志
int scan = (int)((lp >> 16) & 0xFF);
bool extended = (lp & (1L << 24)) != 0;
bool keyUp = (msg == WM_KEYUP || msg == WM_SYSKEYUP);
foreach (RdpSession t in _targets) t.SendScanCode(scan, extended, keyUp);
```

组合键天然正确——Shift/Ctrl/Alt 自己也是按键消息，同样被镜像。扫描码为 0 的注入键（输入法合成）用 `VkKeyScan` 反查兜底。

## 鼠标广播：坐标线性换算

鼠标没有官方注入接口，用 `PostMessage` 直接投递。核心是坐标换算——SmartSizing 是线性缩放，所以按分格尺寸比例换算即可：

```csharp
// 消息目标可能是 ActiveX 内部子窗口，先换算到主控件客户区
POINT pt = { GET_X_LPARAM(lParam), GET_Y_LPARAM(lParam) };
MapWindowPoints(m.HWnd, _masterRoot, ref pt, 1);

foreach (RdpSession t in _targets)
{
    Size ts = t.GetClientSize();
    int tx = pt.X * ts.Width  / masterSize.Width;   // 线性换算
    int ty = pt.Y * ts.Height / masterSize.Height;
    PostMessage(t.Handle, msg, wParam, MAKELPARAM(tx, ty));
}
```

细节决定体验：

- 空移动（没按键的 WM_MOUSEMOVE）按 **30ms 节流**，避免消息洪泛；拖拽时不节流，保证轨迹连续
- 滚轮的 lParam 是屏幕坐标，直接转发
- 整个过滤器**永不拦截消息**（`PreFilterMessage` 恒返回 false），主控会话的体验不受任何影响

## 一个重要的架构确认：投递给谁？

PostMessage 的目标句柄选错，整个鼠标广播就是空转。我写了个小诊断程序枚举控件的窗口树：

```
根窗口句柄: 2174276
根类名: ATL:00007FFA0F363010
（无子窗口）
```

结论：AxHost 的根窗口类名是 `ATL:...`，**它本身就是 OCX 窗口且没有子窗口**——PostMessage 直接投它就是对的。这种"花 10 分钟写个诊断程序确认架构假设"的事，比连接失败后瞎猜便宜得多。

## 多画面布局：近方阵

`SessionGridPanel` 纯自绘布局，自动模式取 `⌈√n⌉` 列，也支持固定 1~4 列；双击标题栏单画面放大。每个分格（SessionTile）= 标题栏（名称/状态灯/广播勾选/放大/关闭）+ RDP 控件主体，还支持拖文件进来触发直传。

## 本篇要点

- 官方接口优先：键盘有 `SendKeys` 就绝不用 PostMessage 模拟
- 可选参数逐项容错，一项不支持不该杀死整个连接
- 架构假设用诊断程序验证，10 分钟换确定的答案
