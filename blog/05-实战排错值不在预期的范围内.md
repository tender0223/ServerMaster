# 05 · 实战排错：值不在预期的范围内

> 《从零写一个多服务器 RDP 批量管理工具》第 5 篇。[系列目录](00-系列总览.md)

程序交付后用户第一次连接真实服务器，就碰了壁：分格上显示

```
失败 · 值不在预期的范围内
```

这篇完整记录排查过程。COM 互操作的错误消息出了名的贫瘠，这个案例是"如何从一句话错误里挖出真相"的典型样本。

## 第一步：确认错误来源

"值不在预期的范围内"是 CLR 对 COM `E_INVALIDARG (0x80070057)` 的标准翻译。代码里只有一处会把原始异常显示出来——连接前的属性设置块：

```csharp
try
{
    _rdp.Server = Server.Host;
    ...
    _rdp.Connect();
}
catch (Exception ex)
{
    SetState(SessionState.Failed, ex.Message);   // ← 用户看到的
}
```

所以问题范围 = `Server`、`UserName`、`DesktopWidth/Height`、`ColorDepth`、`RDPPort`、`ClearTextPassword`、十余个可选参数、或 `Connect()` 本身。

## 第二步：逐属性隔离测试

开发机就是用户机器，可以完全复现。写了个 PowerShell STA 脚本，**每个属性单独 try/catch**：

```powershell
function T([string]$name, [scriptblock]$action) {
    try { & $action; Write-Host "OK   $name" }
    catch { Write-Host ("FAIL " + $name + " : " + $_.Exception.Message) }
}
T 'Server'          { $ax.Server = 'zzw1.example.com' }
T 'DesktopWidth'    { $ax.DesktopWidth = 1119 }
T 'RDPPort=2049'    { $a2.RDPPort = 2049 }
...
```

结果出乎意料：**全部通过**。也就是说属性本身没问题——问题出在我没有复现的那份"实际值"。

## 第三步：看真实数据

直接读用户的 config.json（密码字段抹掉），瞬间真相大白：

```json
{
  "Host": "zzw1.example.com:22381",
  "Port": 3389
}
```

用户把**端口写进了主机栏**（这是最自然的填法——云服务器的 RDP 端口经常不是 3389）。而 Win10 的 mstscax `Server` 属性**拒绝带冒号的字符串**。用真实值验证：

```powershell
T 'Server=host:22381' { $ax.Server = 'zzw1.example.com:22381' }   # FAIL 值不在预期的范围内
T 'Server=纯host'      { $ax.Server = 'zzw1.example.com' }        # OK
T 'RDPPort=22381'      { $ax.AdvancedSettings2.RDPPort = 22381 } # OK
```

根因实锤。老版 mstsc.exe 的界面允许填 `host:port`，是因为**UI 层自己解析后设 `RDPPort`**，控件本身从不接受这种写法。

## 第四步：修复（双保险）

**解析器**——处理 `host:port`、`[IPv6]:port`、裸 IPv6 等所有形态：

```csharp
public static bool Split(string raw, out string host, out int port)
{
    // [ipv6]:port 或 [ipv6]
    if (host[0] == '[') { ... }
    // 恰好一个冒号且冒号后为数字 → host:port
    // （裸 IPv6 有多个冒号，不会误伤）
    int colon = host.IndexOf(':');
    if (colon > 0 && host.IndexOf(':', colon + 1) < 0)
    {
        int p;
        if (int.TryParse(host.Substring(colon + 1), out p)) { ... return true; }
    }
    return false;
}
```

- **会话层**防御性拆分：存量配置不用改就能连
- **编辑对话框**：保存时拆分并回显，新数据落库即规范

再配上 11 组单元测试（含 IPv6、非法输入边界），以及上篇说过的可选参数逐项 `TrySet` 降级。

## 经验总结

1. **COM 错误消息没有信息量时，用真实数据复现**——我先用"我认为的值"测了一遍全过，差点得出"没问题啊"的结论。真实用户的输入永远比你的测试用例更有想象力
2. **逐属性隔离**是把范围从"十几处"缩到"一处"的最快手段，脚本 10 分钟写完
3. 报错路径要保留原始异常文本（`ex.Message`），虽然难看，但它是排错的唯一线索
4. UI 输入要按用户的真实习惯设计（`host:port` 就是大家的习惯），而不是要求用户迁就实现
