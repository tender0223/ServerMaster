# 07 · 用户反馈驱动的迭代

> 《从零写一个多服务器 RDP 批量管理工具》第 7 篇。[系列目录](00-系列总览.md)

工具投入使用后，真实用户的反馈以截图形式源源不断地来。这一篇挑三个有代表性的：一个架构级教训、一个显示 bug、一个构建脚本事故。

## 教训一：显示缩放 ≠ 会话分辨率（架构级）

用户反馈：连接十几台服务器后，**服务器上正在运行的程序窗口被挤压变形**。

### 根因

我最初为了"画面铺满分格"，把**远端会话的桌面分辨率**设成了分格大小——16 台同屏时每格只有约 460×260。RDP 一连接，服务器整个桌面被改成这个分辨率，Windows 重排所有窗口：游戏窗口错位、程序界面挤压。

这里混淆了两个完全不同的概念：

| 概念 | 是什么 | 应该动吗 |
|------|--------|----------|
| **会话分辨率** | 服务器桌面"真实"的大小，改变它 = 重排所有窗口 | ❌ 绝不 |
| **显示端缩放** | 客户端把远端画面等比缩小画在分格里（SmartSizing） | ✅ 随便 |

### 修复

连接时使用**固定分辨率**（默认 1920×1080，全局可改、每台服务器可覆盖），分格里只做显示端缩放：

```csharp
// 远端分辨率固定（服务器桌面分辨率不被改变），
// 画面按分格大小等比缩放显示（SmartSizing 纯显示端缩放）
int w = s.DesktopWidth  > 0 ? s.DesktopWidth  : _cfg.Settings.DesktopWidth;
int h = s.DesktopHeight > 0 ? s.DesktopHeight : _cfg.Settings.DesktopHeight;
```

此后连接、断开、布局切换、窗口缩放都不再碰服务器的分辨率。给用户的建议也简单：把默认分辨率设成你平时远程桌面用的值，程序窗口连位置都不用动。

**教训：远程桌面场景下，"看起来多大"和"实际多大"是两个维度，UI 的布局需求永远不应该外溢到被控端。**

## Bug 一：列表里显示类名

批量传输窗口的"目标服务器"列表赫然显示一排 `ServerMaster.Models.ServerInfo`——`CheckedListBox` 显示的是 `ToString()`，而我忘了重写。一行修复：

```csharp
public override string ToString()
{
    return DisplayName + " (" + Host + ":" + Port + ")";
}
```

顺手把整个窗口打磨了一遍：已连接的服务器自动勾选、开始按钮实时显示"开始上传(N台)"、列表加宽。**凡是把对象直接丢给列表控件的场合，永远先确认 ToString 的输出。**

## 事故：一行中文注释让构建静默失效

某次给 `build.cmd` 加了一行中文 `rem` 注释，结果之后所有构建**静默失败**——批处理输出里混着 `'b.dll' 不是内部或外部命令` 这种鬼话。

根因：cmd.exe 用 **GBK（OEM 代码页）逐字节解析批处理**，而文件是 UTF-8。中文注释的多字节序列让解析器错位，把后续命令行的碎片当成了独立命令——编译根本没执行，旧 exe 还在原处，一切看起来"正常"。

规则从此写进脚本头注释：

```bat
rem  NOTE: keep this file ASCII-only. cmd.exe parses batch files
rem        in the OEM/ANSI codepage, non-ASCII text corrupts it.
```

顺带修出了**热替换构建**：程序运行时 exe 被锁定，构建产物保留为 `ServerMaster.new.exe`，下次构建自动换名——用户开着程序也能随时出新版本。

## 期间交付的其他迭代（清单）

- **组织能力**：勾选分组→"删除勾选"批量删、按组删除、全部删除、**拖拽服务器到其他分组**、分组重命名（重名自动合并）
- **输入细节**：编辑框粘贴 `host:port` 自动拆分（监听 `WM_PASTE`，不影响手动输入）
- **文件直达**：拖文件到分格 = SMB 直传到服务器目标目录（失败自动降级为剪贴板方案）
- 每台服务器的远端分辨率独立覆盖、颜色深度可选、控制台会话开关

## 迭代方法论

1. 用户截图 + 一句话抱怨，通常就够定位问题——**前提是日志和状态栏把真实错误显示出来**（见 05 篇）
2. 每个修复都做**二进制字符串级验证**（确认新 exe 里真的包含新功能的字符串），杜绝"以为编译进去了"
3. 小版本号高频发布：v0.2.0 → v0.2.1 → v0.2.2 → v0.2.3，每个版本对应一次用户反馈闭环
