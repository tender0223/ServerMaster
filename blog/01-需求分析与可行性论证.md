# 01 · 需求分析与可行性论证

> 《从零写一个多服务器 RDP 批量管理工具》第 1 篇。[系列目录](00-系列总览.md)

动手写代码之前，我花了整个第一阶段只做两件事：把需求翻译成可验证的技术命题，然后逐条证明它可行。事后看这个阶段非常值得——后面所有架构决策都能追溯到这里的结论。

## 需求拆解

用户的原始诉求只有一句话："在一个程序窗口里同时观看多个 Windows Server 的运行画面，并且可以对一个或多个服务器同时操作和传输文件。"拆开后是五个可验证的需求：

| 编号 | 需求 | 验证方式 |
|------|------|----------|
| R1 | 多画面同屏 | 一个窗口内 N 个独立 RDP 会话同时渲染 |
| R2 | 单台操作 | 点击任意画面，像本机一样操作 |
| R3 | 多台同步操作 | 主控画面的键鼠在勾选的画面上同步复现 |
| R4 | 文件传输 | 本地文件直达单台/多台服务器的指定目录 |
| R5 | 服务器管理 | 分组、凭据存储、批量连接断开 |

## 先例调研：这条路有人走通过吗

可行性论证最快的方式是找先例。三个成熟产品证明核心技术路线成立：

- **mRemoteNG**（开源）：WinForms 内嵌 mstscax ActiveX，单窗口管理大量 RDP 会话 → 证明 R1
- **Remote Desktop Manager**：标签/平铺多会话 + 文件传输 + 凭据库 → 证明 R1+R4
- **Royal TS**：多画面平铺 + 输入广播到多连接 → 证明 R3

三个需求都有先例，意味着不存在"需要发明新技术"的风险，剩下的只是工程整合。

## 三项核心命题的逐条论证

### R1 多画面：mstscax 支持多实例

微软官方 RDP 客户端控件 `mstscax.dll` 是标准 ActiveX，可以在 WinForms 中以 `AxHost` 方式创建**多个实例**，每个实例独立连接一台服务器的独立会话。关键参数 `SmartSizing=true` 让远端画面自动缩放适配分格大小——这是"小格子看大桌面"的基础。

### R3 输入广播：官方注入接口 + 消息镜像

- **键盘**：控件官方接口 `IMsRdpClientNonScriptable::SendKeys(numKeys, pbArrayKeyUp[], plKeyData[])` 允许程序按扫描码向远端会话注入按键。宿主窗口用 `IMessageFilter` 旁听主控会话的按键消息，镜像调用其他会话的 `SendKeys`——这是官方支持的注入通道，不是黑科技。
- **鼠标**：没有官方注入接口，用 `PostMessage` 向目标会话控件句柄投递 `WM_LBUTTONDOWN/UP`、`WM_MOUSEMOVE` 等消息，坐标按各分格尺寸线性换算（SmartSizing 的缩放是线性的，所以换算是解析的）。

### R4 文件传输：三条互补通道

| 通道 | 原理 | 适用 |
|------|------|------|
| SMB 管理共享（主通道） | `WNetAddConnection2` 建立凭据会话后直接对 `\\主机\c$\...` 流式复制 | 批量分发到 N 台，可编程 |
| RDP 剪贴板 | 本地 `CF_HDROP` → 远端 Ctrl+V | 快速单次 |
| 驱动器重定向 | `RedirectDrives=true`，远端可见 `\\tsclient\C` | 会话内临时拖拽 |

SMB 通道要求 445 端口开放且账号有管理员权限——云 Windows 服务器基本都满足。

## 技术选型：五个候选的取舍

| 方案 | 优点 | 致命伤 | 结论 |
|------|------|--------|------|
| **WinForms + mstscax** | 官方控件、兼容性最好、零部署 | 仅 Windows | ✅ 选定 |
| WPF + WindowsFormsHost | UI 现代 | 双 UI 栈包一层，无本质收益 | ❌ |
| FreeRDP 自绘 | 跨平台 | 协议栈工作量大数倍 | ❌ |
| 服务器端 Agent | 可控性强 | 每台都要装，侵入+安全风险 | ❌ |
| VNC | 简单 | 要额外装服务端、无加密 | ❌ |

目标框架选 **.NET Framework 4.8** 而不是 .NET 6/8，理由很实际：Win10/Server 2019+ 系统自带运行时，**exe 拷过去就能跑**，用户不需要装任何东西。

## 诚实声明约束

可行性论证必须包含反面：

1. 每台 Windows Server 默认只允许 **2 个并发管理 RDP 会话**——但对"N 台服务器各 1 路"无限制，本工具正是后一种模式
2. 广播鼠标是坐标镜像的近似实现，个别程序（DirectInput/RawInput 游戏）可能不响应
3. 密码用 DPAPI（当前用户作用域）加密，导出配置到别的机器需重新录入——安全优先的取舍
4. 只能运行在 Windows 管理机上（ActiveX 是 Windows 组件）

## 本篇要点

- 可行性论证 = 先例 + 逐条技术命题 + 明确的约束声明，三者缺一不可
- 选型时"零部署"这个运维属性可以压倒"技术更新"
- RDP 官方控件自带 `SendKeys` 注入接口，这是广播键盘的合法通道，先查文档再造轮子
