# 02 · 总体架构设计

> 《从零写一个多服务器 RDP 批量管理工具》第 2 篇。[系列目录](00-系列总览.md)

可行性确认后，我把整个系统画成一张图再开始写代码。这个项目最终的代码量不大（20 个源文件），但分层保证了每一层都可以独立排错——后面的排错故事能这么快定位，全靠这一步。

## 三层架构

```
┌────────────────────────────────────────────────────────┐
│                    ServerMaster.exe                    │
│                                                        │
│  UI 层 (WinForms)                                      │
│  MainForm ─ ServerListPanel(左) ─ SessionGridPanel(中)  │
│                    │                  │                 │
│                    │        ┌─ SessionTile × N ─┐      │
│                    │        │ 标题栏/状态/广播勾选   │    │
│                    │        │  RdpSession(AxHost) │    │
│                    │        └────────────────────┘     │
│  ───────────────────┼────────────────────────────────  │
│  服务层              │                                  │
│  ConnectionManager  会话生命周期/批量连接                  │
│  InputBroadcastService  IMessageFilter 键鼠镜像          │
│  ConfigStore / PasswordProtector / AppLogger            │
│  SmbChannel / ClipboardChannel  文件传输通道              │
│  ───────────────────┼────────────────────────────────  │
│  互操作层            │                                  │
│  RdpSession ── AxMsRdpClient9 (mstscax ActiveX × N)     │
│  KeyMapper(扫描码)   Win32 NativeMethods(P/Invoke)       │
└────────────────────────────────────────────────────────┘
```

分层原则：**UI 层不直接碰 ActiveX 接口**，一切通过 `RdpSession` 封装。后来 mstscax 的事件参数类名、属性取值范围等种种坑，全部被隔离在互操作层里。

## 关键机制一：输入广播是"叠加"而非"抢占"

这是整个系统里最容易设计错的交互。我的原则：

- **主控会话**永远正常响应用户（R2 优先保证）
- 勾选了"广播"的会话同步接收镜像输入（R3 是附加行为）
- 用户随时可以关掉广播，主控不受任何影响

实现上用 `IMessageFilter` 做消息**旁听**（只看不拦）：

```
用户键鼠 ─▶ Windows 消息队列 ─▶ 主控分格的 mstscax（正常处理）
                     │
                     ▼ PreFilterMessage（不拦截）
         判定：消息目标 == 主控会话窗口 && 广播开启
                     │
          ┌──────────┴──────────┐
          ▼ 键盘                 ▼ 鼠标
   提取 lParam 扫描码        提取客户区坐标
   (+扩展键标志)             按目标分格尺寸线性换算
          ▼                      ▼
   target.SendKeys(...)    PostMessage(target, WM_xBUTTONDOWN, ...)
```

## 关键机制二：会话状态机

每个 RDP 会话是一条独立状态机，掉线自动重连：

```
Disconnected ─Connect()─▶ Connecting ─OnConnected─▶ Connected
     ▲                       │                          │
     │手动断开/重试耗尽         OnFatalError              意外掉线(代码≠260)
     └───────────────────────┴────────▶ Failed ◀───────┘
                              Reconnecting ◀─ 5秒间隔×5次
```

状态码 260 是客户端主动断开，其余视为意外掉线进入重连。UI 层只订阅 `StateChanged` 事件刷新状态灯（灰/黄/绿/红），完全不知道重连细节。

## 关键机制三：文件传输三通道

| 通道 | 实现 | 场景 |
|------|------|------|
| SMB 管理共享 | `WNetAddConnection2` → 流式复制 → `WNetCancelConnection2` 用完即断 | 多台批量分发 |
| RDP 剪贴板 | `Clipboard.SetFileDropList` + RDP 剪贴板重定向 | 远端 Ctrl+V |
| 拖放直传 | 拖文件到分格 → SMB 直传目标目录 | 单台快速 |

SMB 凭据只在传输期间存在，传输完立刻断开会话——不驻留凭据。

## 数据模型与存储

配置存 `%APPDATA%\ServerMaster\config.json`，用 .NET Framework 自带的 `JavaScriptSerializer`（零外部依赖），保存时"临时文件 + 替换"保证原子性：

```json
{
  "Servers": [{
    "Id": "3f2a…(GUID)",
    "Name": "Web服务器01",
    "Host": "192.168.1.10",
    "Port": 3389,
    "EncryptedPassword": "AQAAANCMnd8…(DPAPI)",
    "Group": "生产环境",
    "ColorDepth": 16,
    "AutoReconnect": true
  }],
  "Groups": ["生产环境", "测试环境"],
  "Settings": { "MaxColumns": 0, "DesktopWidth": 1920, "DesktopHeight": 1080 }
}
```

密码用 **DPAPI（CryptProtectData，CurrentUser 作用域 + 应用熵）**加密：密文只有本机本 Windows 账户能解。导出配置到其他机器密码失效——这是特性不是缺陷。

## 安全设计清单

- 密码密文落盘，内存中解密后立即交给 RDP 控件，不回显
- RDP 启用 NLA（CredSSP）
- SMB 凭据用完即 `WNetCancelConnection2`
- 写操作进审计日志

## 本篇要点

- 先画架构再写代码，分层是后来快速排错的基础
- 广播输入设计成"叠加而非抢占"，单机体验永远不被批量功能绑架
- 状态机把"连接"这种脏活封装在互操作层，UI 只看状态灯
