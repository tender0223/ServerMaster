# 09. 键盘注入攻坚战：四轮失败、锁屏陷阱与最终打通

> 系列第 9 篇。前面所有功能都一次或两次迭代就工作了，唯独「广播输入」——把主控窗口的键盘操作实时镜像到其他 RDP 分格——连续四个版本都报"无效"。这篇记录整个排错过程：三个隐蔽的陷阱，和一套用来定位它们的可视化实验台方法。

## 现象与错误方向

广播链路分两段：**捕获**（WH_KEYBOARD_LL 低级钩子，拿到 vk + 扫描码）和**注入**（把按键送进每个目标分格的 mstscax 控件）。遥测日志早就证明捕获段完美：钩子能看到每个键、主控焦点判定正确、目标队列正常。

问题全在注入段。先后试了三种"正统"方法，全部无效：

1. `IMsRdpClientNonScriptable.SendKeys`——微软文档里专门用来向控件发送按键的接口；
2. `PostMessage(WM_KEYDOWN/WM_KEYUP)`——投递完整消息，lParam 按规范构造（重复数、扫描码位、扩展位、过渡位）；
3. `keybd_event`——合成"真实"键盘事件，走系统全部输入路径，配焦点轮转（SetFocus 到目标控件再注入）。

每种都"应该"有效，每种都毫无反应。用户在远端看不到任何键出现。

## 教训一：无人锁屏的机器上，UI 注入实验全部作废

为了做端到端验证，我写了一个实验台程序：真实连接一台服务器，依次注入 `Ctrl+Esc → notepad → 回车`，每种方式后对控件区域截图，看远端开始菜单是否打开。

第一轮实验的截图"成功"拍到了锁屏画面——我一度以为远端服务器锁屏了。后来在实验台里加了环境自检才发现真相：

```
session desktop=Default
foreground=0x7174E  fg-proc=LockApp
```

**前台窗口属于 LockApp（Windows 锁屏应用）**——是本地机器锁屏了。用户测试完说了"不行"就锁屏离开，之后所有实验都在锁屏桌面上运行：

- `keybd_event` 注入的键落在锁屏界面，无人接收；
- `CopyFromScreen` 拍到的"远端锁屏"其实是本地锁屏（控件还没渲染出来，截到的是控件后面的本地画面）；
- 后来换 `DrawToBitmap` 离屏截图——mstscax 用 DirectX 渲染，返回 100% 纯黑。

结论：**判定链路必须有独立于屏幕截图的可观察量**，而且实验开始前必须自检会话状态（`OpenInputDesktop` 返回的桌面名、前台窗口进程名）。

## 教训二：keybd_event 发给"前台"，SetFocus 只管"自己"

第二个陷阱更深。实验台加了本地对照实验：窗体里放一个 TextBox，`SetFocus` 过去再用 `keybd_event` 打 `ab1`，结果文本框是空的。

原因：**`keybd_event`/`SendInput` 注入的是系统全局输入流，操作系统把它投递给"前台线程的焦点窗口"**。而 `SetFocus` 只修改**调用线程自己消息队列内**的焦点——如果我的窗口不是前台，焦点切了也白切，注入的键全部飞给当时真正的前台窗口。

所以注入前必须先拿到前台。实验台的两段式抢前台：

1. `AttachThreadInput` 与当前前台线程共享输入队列，再 `SetForegroundWindow`；
2. 兜底：合成一次**真实鼠标点击**自己的标题栏（真实用户输入的优先级凌驾于前台锁之上）。

## 教训三（根因）：KeyboardHookMode 默认吃掉组合键

前两个陷阱解决后，实验终于能在解锁的机器上跑出真实结果。实验矩阵四种方式：

- E1：前台 + SetFocus + `keybd_event` Ctrl+Esc；
- E2：真实鼠标点击控件 + `keybd_event`；
- E3：`SendKeys` 接口注入 Win 键；
- E4：`PostMessage`（对照）。

结果 E1、E3 双双生效：截图里远端（Windows Server 2012）的开始屏幕被 Ctrl+Esc 打开、被 Esc 关闭；E5 全流程里 `notepad` 这个词出现在远端开始屏幕的搜索框里——字母注入铁证到达远端。

但用户手里同样配方的 v0.3.0 却"无效"。差别在实验台多设了一个参数：

```csharp
((IMsRdpClientSecuredSettings2)ax.SecuredSettings).KeyboardHookMode = 1;
```

mstscax 的 `KeyboardHookMode` 默认为 0——**"仅全屏模式转发组合键"**。窗口化嵌入的控件里，Win / Ctrl+Esc / Alt+Tab 这些组合键会被**本地吃掉，根本不进远端**。所以之前的注入测试（Ctrl+Esc 开菜单 → notepad → 回车）第一键就断在本地：开始菜单从没在远端开过，"notepad" 打进了远端当时聚焦的游戏窗口，回车无效果——用户看到的就是"没有任何反应"。

这个属性属于 `IMsRdpClientSecuredSettings2`（安全设置接口），**只能在连接成功之后设置**，所以要在 `OnConnected` 事件里做，并配降级容错。

## 落地修复（v0.3.1）

1. **`RdpSession.OnConnected`：`KeyboardHookMode = 1`**——组合键全部转发远端，广播场景的生死开关；
2. **注入节奏**：实验台验证 down/up 间隔 40–90ms 稳定有效，所有注入点（广播队列、批量推送 Ctrl+V、注入自测）统一改为此节奏，连发会被远端丢弃；
3. **前台安全闸**：`keybd_event` 注入全局输入流，若本程序不在前台则丢弃队列/中止推送——否则用户切去别的程序打字时，镜像键会打进别人的窗口；
4. **注入自测按钮重写**：按已验证配方发送 `Ctrl+Esc → notepad → 回车`，弹窗告诉用户判定标准（远端弹出记事本 = 链路正常），并记录前台句柄遥测。

## 方法论沉淀

- **分层判定**：捕获段用日志遥测，注入段用可视化实验台，环境段（前台/桌面/锁屏）先自检——三层各找各的证据；
- **本地对照**：注入远端之前先注入本地 TextBox，一行代码把"注入方法坏了"和"目标接收坏了"分开；
- **金丝雀思维**：`PrtSc` 键不需要远端任何窗口配合，截屏进远端剪贴板还会经 RDP 剪贴板通道回同步本地——是天然的全链路探针（注意本地 PrtSc 也会写本地剪贴板，需靠图像内容区分来源）；
- **无人值守机器不跑 UI 实验**：锁屏之下一切输入类实验都是负结果，先查 LockApp。

下一个版本目标是：广播鼠标镜像的同等验证，以及把注入节奏做成自适应（按目标数量动态调整批大小）。
