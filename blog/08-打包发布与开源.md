# 08 · 打包发布与开源

> 《从零写一个多服务器 RDP 批量管理工具》第 8 篇（完结）。[系列目录](00-系列总览.md)

功能稳定后，最后一步是让工具能被"另一个地方的另一个人"直接用起来——打包、验证、开源。

## 绿色版：为什么能做到零安装

技术选型时就埋好了伏笔——.NET Framework 4.8 是 Win10/Server 2016+ 系统自带的。所以"绿色版"只需要：

```
ServerMaster.exe          主程序
AxMSTSCLib.dll            RDP 互操作（AxImp 生成）
MSTSCLib.dll              RDP 接口定义
README.md / LICENSE / docs\设计文档.md
```

压缩后不到 400KB，解压双击即用，不需要安装任何运行时。

## 打包与验证：不看截图看字节

打包脚本用 PowerShell 的 `Compress-Archive`，源码包用 `git archive`（天然只含已提交文件）。但比打包更重要的是**验证**——我踩过"以为编译进去了"的坑，所以验证是字节级的：

```powershell
# 解压后独立运行 3 秒
$p = Start-Process '...\ServerMaster.exe' -PassThru
Start-Sleep 3
if ($p.HasExited) { 'FAIL' } else { 'OK'; Stop-Process $p.Id }

# 包内 exe 做字符串级版本确认（.NET 字符串字面量在 #US 堆里是 UTF-16）
$text = [Text.Encoding]::Unicode.GetString($exeBytes)
if ($text.Contains('设置默认远端分辨率')) { 'v0.2.1 ✓' }
```

解压 → 运行 → 字符串校验，三步做完才敢交付。

## MIT：为什么选它

需求是"公开仓库，允许别人修改二创"。MIT 是最宽松的主流选择：允许使用、修改、再分发、甚至商用，只需保留版权声明。一个文件搞定：

```
MIT License

Copyright (c) 2026 ServerMaster contributors

Permission is hereby granted, free of charge, to any person obtaining a copy
of this software ... to deal in the Software without restriction ...
```

## Git 仓库与发布流程

本地仓库一开始就规划好：`.gitignore` 排除构建产物、提交粒度对应版本、每个版本打 tag：

```bat
git init -b main
git add -A
git commit -m "v0.2.3: ..."
git tag v0.2.3
```

发布到 GitHub 两条路（写在仓库的 `发布到GitHub.md` 里）：

```bat
:: 方式一：GitHub CLI 一条命令
gh auth login
gh repo create ServerMaster --public --source=. --push

:: 方式二：网页建仓库后
git remote add origin https://github.com/<用户名>/ServerMaster.git
git push -u origin main
```

## 结束语

回顾整个研发过程，最值得复用的三条：

1. **可行性先行**——先例调研 + 逐条技术命题验证，让后面每一步都有据可依
2. **真实数据复现**——所有诡异 bug（host:port、FinalShell 4.x 算法、分辨率挤压）都是在真实数据面前现形的
3. **验证到字节级**——发布前解压运行 + 字符串校验，比"应该没问题"可靠一万倍
